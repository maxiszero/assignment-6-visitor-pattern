# Защита Assignment 6 — Visitor

## Суть за 30 секунд

> У меня есть одно дерево: файлы и папки. Мне нужно выполнять над ним разные операции: сложить размеры файлов, найти элементы по имени, посчитать количество файлов и папок. Каждая операция живёт в отдельном классе visitor. Обход передаёт visitor каждому элементу через `accept`. Файл вызывает `visitFile(this)`, папка — `visitDirectory(this)`. Поэтому для третьей операции я добавил новый visitor, а классы файлов и папок оставил прежними.

Представь, что у тебя одна папка с документами. Один человек считает их общий размер, другой ищет документ по названию. Папка и документы одни и те же, задача у каждого человека своя. В программе visitor — объект, который выполняет одну такую задачу и хранит её результат.

## Что запустить перед преподавателем

Эти команды можно вставить в PowerShell из любой папки:

```powershell
powershell -ExecutionPolicy Bypass -File "D:\projects\visitor-pattern-assignment\build.ps1" demo
powershell -ExecutionPolicy Bypass -File "D:\projects\visitor-pattern-assignment\build.ps1" extension
powershell -ExecutionPolicy Bypass -File "D:\projects\visitor-pattern-assignment\build.ps1" test
```

1. **demo**: первое число — `6000 bytes` (1200 + 2400 + 600 + 1800). Поиск `.txt` выводит три имени. Поиск `docs` находит папку.
2. **extension**: показывает `File count: 4` и `Directory count (including root): 3`. Папки: `project`, `src` и `docs`.
3. **test**: в конце должно быть `PASS: 20 tests`. Если попросят только собрать, замени `test` на `compile`: команда выведет сообщение об успешной компиляции.

Последнее слово (`demo`, `extension`, `test` или `compile`) — режим файла `build.ps1`. `-File` указывает путь к этому скрипту. `-ExecutionPolicy Bypass` позволяет запустить скрипт в этом новом процессе PowerShell и не меняет настройки системы. Если проект перенесёшь, замени путь до `build.ps1`.

## Как объяснить double dispatch

Возьми `README.txt` и `SizeCalculatorVisitor`:

```text
walker: element.accept(visitor)
             ↓ Java видит, что element — FileNode
FileNode.accept: visitor.visitFile(this)
             ↓ Java видит, что visitor — SizeCalculatorVisitor
SizeCalculatorVisitor.visitFile: добавляет 1200 байт
```

Если элемент — папка, первый выбор приведёт в `DirectoryNode.accept` и там вызовется `visitDirectory`. Если visitor — `SearchVisitor`, второй выбор приведёт в метод поиска. Поэтому итоговое действие зависит и от **вида элемента**, и от **выбранной операции**. `this` — тот объект, на котором сейчас выполняется `accept`: конкретный файл или папка.

## Что могут спросить

| Вопрос | Ответ |
| --- | --- |
| Почему нельзя просто сделать `visit(element)` в обходчике? | Обходчик видит переменную типа `FileSystemElement`. Внутри `accept` конкретный класс знает, какой из методов интерфейса вызвать. Нет цепочки проверок типов. |
| Кто обходит дерево? | `FileSystemWalker`. Сначала вызывает `accept` на текущем элементе, потом идёт по его детям. Visitor выполняет только операцию над уже выбранным элементом. |
| Где показано добавление операции? | В `ElementCountVisitor.java` и `ExtensionDemo.java`. Можно показать коммит с сообщением `feat: add a counting visitor without changing element classes`. |
| Что если добавить новый вид элемента, например ссылку? | Понадобятся новый класс, `visitLink` в интерфейсе и реализация в каждом visitor. Visitor удобен, когда виды элементов стабильны, а операций становится больше. |
| Не нарушается ли инкапсуляция? | Поля закрыты. Visitor читает имя и размер через методы, а список детей нельзя изменить снаружи. При этом добавление visitor иногда требует новых геттеров, если текущего интерфейса не хватает. |
| Что из главы 12? | Тесты проверяют поведение; рекурсия написана один раз; имена методов показывают назначение; интерфейс содержит только нужные методы для двух видов элементов. |
| Что из главы 13? | Папка сохраняет неизменяемый снимок списка детей. Каждый обход использует свой visitor, поэтому счётчик и список результатов не делятся между потоками. Есть тест двух параллельных обходов. |
| Можно использовать один `SizeCalculatorVisitor` несколько раз? | Он накопит байты от обоих обходов. Для отдельного результата создаю новый экземпляр. Один экземпляр между потоками не делю. |
| Почему у папки в size visitor пустой метод? | Размер в задании — сумма содержимого файлов. Папка сама байты не добавляет, а до каждого файла добирается обходчик. |
| Чем отличается от Strategy из 5-го? | Strategy меняет способ выполнения одной задачи. Visitor добавляет отдельную операцию для разных видов объектов одной структуры. |
| Чем отличается от Facade из 4-го? | Facade давал один удобный вызов для набора устройств кинотеатра. Visitor позволяет пройти по одним и тем же объектам с разными задачами. |

Если просят показать что-нибудь одно, открой `FileNode.accept` и `SizeCalculatorVisitor.visitFile` рядом. Это самая короткая цепочка, на которой виден смысл паттерна.
